Integration

Connecting a new app to this service.

Six steps

  1. Create the app. The id becomes PAYMENT_APPLICATION_ID and cannot be changed. Add localhost to the allowed return hosts while you develop.
  2. Add plans. Amounts are in minor units — 2900 is $29.00. Anything above zero creates a Stripe product and price on first save. Then set the free plan code in Settings.
  3. Issue a key. Four values, shown once: 
    PAYMENT_SERVICE_URL={{ base_url }}
PAYMENT_APPLICATION_ID=yourapp
PAYMENT_KEY_ID=...
PAYMENT_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n"
  4. Sign every call. A fresh 60-second Ed25519 token in x-api-key. 
    new SignJWT({})
  .setProtectedHeader({ alg: "EdDSA", kid: process.env.PAYMENT_KEY_ID })
  .setIssuer(process.env.PAYMENT_APPLICATION_ID)  // matches the app id in the URL
  .setAudience("payment-service")
  .setSubject(tenant)       // from your session, never a request body
  .setJti(randomUUID())
  .setExpirationTime(now + 60)
  .sign(key);
  5. Gate on entitlements. 
    GET /v1/apps/{app}/entitlements
→ { "plan_code": "pro", "active": true, "in_grace_period": false, ... }

    Gate writes, not reads. When this service is unreachable, keep the last plan you saw rather than treating it as no plan.

  6. Checkout. 
    POST /v1/apps/{app}/checkout/session  → { "url": ... }
POST /v1/apps/{app}/billing/portal    → { "url": ... }

    A 409 means the store already subscribes — send it to /subscription/change instead.

Four things that catch people

The field is plan_code, not plan. This service answers in snake_case, so the camelCase name gives undefined with no error and the plan looks permanently missing.

Break out of the iframe for Stripe. It sends X-Frame-Options: DENY. Inside an admin panel, location.href gives a blank frame and no error — use window.top.location.href.

The tenant comes from your session. It is signed into sub and decides whose billing is touched. Read it from a request body and anyone can buy or cancel on someone else's behalf.

Point Stripe at the webhook. {{ base_url }}/webhooks/stripe/{app}, with its signing secret on the app's record. Without it a checkout never reaches the entitlements your app reads.

Testing without paying

Create a coupon on the app's page. It is a Stripe promotion code at 100% off, forever, so the store ends up with a real subscription at zero — active status, webhooks fired, entitlements unchanged. Nothing in your app needs an if (testing) branch.

Minimum eight characters. Each is restricted to its own app's products, so a code made here cannot be redeemed on another app's checkout.
